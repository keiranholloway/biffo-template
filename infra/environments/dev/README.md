# infra/environments/dev

Root Terraform configuration for the `dev` environment. See `../../../CLAUDE.md` for the overall repo layout and `../../../docs/ADR/` for the architecture decisions this config implements — in particular:

- **ADR-0001** — every table/API/event carries `tenant_id`.
- **ADR-0002** — only the Core API's Lambda (`module.core_api`) talks to the database; every other service, including plugins, calls the Core API over HTTPS and reacts to EventBridge events.
- **ADR-0003** — the plugin system this doc's "Adding a plugin" section wires into.

## Usage

```bash
cd infra/environments/dev
terraform init -backend-config=backend.hcl
terraform plan
```

`backend.hcl` is generated by `biffo init`/CI, not committed — see `../../../scripts/bootstrap.sh`.

## Module layout

`main.tf` instantiates, in order: `networking` → `storage` → `cdn` → `auth` → `events` → `database` → `core_api` (compute) → `api_gateway`. Each module lives under `../../../modules/cloud/aws/<name>` and follows the pluggable variable/output convention described in `CLAUDE.md`'s "Pluggability" section.

## Adding a plugin

Plugins (ADR-0003) are provisioned via the `enabled_plugins` variable (`variables.tf`) and one `module "plugin_<name>"` block per plugin in `main.tf`.

**Why one block per plugin, not a generic loop:** Terraform requires a module's `source` argument to be a static string literal — it cannot be interpolated from `var.enabled_plugins` at runtime. So this config can't dynamically discover `modules/plugins/*` the way, say, `discover_plugin_manifests()` does for `services/*/biffo.plugin.json` in the Core API (`services/api/src/api/plugins.py`). Each plugin needs its own explicit, individually-gated module block.

### Steps

1. Install the plugin: `biffo plugin install <name>@<minor>` (issue #20) clones the plugin's source into `services/<name>/` and copies its `terraform/` directory into `modules/plugins/<name>/`. If the plugin ships no `terraform/` directory, copy `modules/plugins/_template/` to `modules/plugins/<name>/` and adjust it yourself — see that module's README for what it wraps and why.
2. Add a module block to `main.tf`'s "Plugin modules" section:

   ```hcl
   module "plugin_<name>" {
     source   = "../../../modules/plugins/<name>"
     for_each = contains(var.enabled_plugins, "<name>") ? { "<name>" = true } : {}

     project_name   = var.project_name
     environment    = local.environment
     plugin_name    = "<name>"
     handler        = "src.lambda.main.handler"
     event_bus_name = module.events.event_bus_name
     core_api_url   = module.api_gateway.api_endpoint
     tags           = local.tags
   }
   ```

3. Aggregate its outputs alongside the existing `output` blocks, e.g.:

   ```hcl
   output "plugin_<name>_function_arn" {
     value = try(module.plugin_<name>["<name>"].function_arn, null)
   }
   ```

4. Add `"<name>"` to `enabled_plugins` in `terraform.tfvars` (or wherever this environment's tfvars live) and `terraform apply`.

### What a plugin module receives — and does not

Every plugin module gets the same standard variables: `project_name`, `environment`, `plugin_name`, `event_bus_name`, `core_api_url`, `tags` (see `modules/plugins/_template/variables.tf`). It does **not** receive `db_credentials_secret_arn`, `vpc_id`, or `private_subnet_ids` by default:

- **No database credentials, ever.** ADR-0002 grants `secretsmanager:GetSecretValue` on the DB secret to the Core API's Lambda role only (`module.core_api` above). A plugin that needs platform data calls the Core API over HTTPS via `core_api_url` (injected as `BIFFO_CORE_API_URL`, read by `BiffoAPIClient` in `packages/python-sdk`).
- **No VPC attachment by default.** Dev runs with `enable_nat_gateway = false` (no NAT — the Core API doesn't need one since it only talks to RDS over the VPC-local network and Cognito JWKS is baked in at `apply` time). A plugin Lambda placed in the private subnets would have *no* outbound internet route at all, so it couldn't reach the Core API's public API Gateway endpoint. Plugin Lambdas therefore run outside the VPC by default (see `modules/cloud/aws/compute/variables.tf`'s `vpc_id` description), which also gives them normal internet egress. Only pass `vpc_id`/`private_subnet_ids` if a plugin has a genuine reason to reach a VPC-only resource that isn't the database.

### Loose coupling

Plugin modules must not reference each other — no plugin's `main.tf` should read another plugin's module outputs or resources. Each is instantiated independently via its own `for_each`-gated block.

## Verification

- `terraform fmt -check -recursive` from the repo root (covers `infra/` and `modules/`).
- `terraform init -backend=false && terraform validate` from this directory — this is what CI's `Terraform Validate & Security` job (`.github/workflows/ci.yml`) runs.
- Checkov and tfsec run against `modules/` in CI with `soft_fail: true` — findings are surfaced but don't block the build.
